# FAKEBOOK 로컬 과제

HTML/CSS/JavaScript로 만든 브라우저 로컬 SNS 실습입니다.

## 실행

프로젝트 폴더에서 `python -m http.server 8000` 실행 후 `http://localhost:8000`에 접속합니다. 같은 브라우저와 같은 주소·포트를 계속 사용하세요. 회원가입 후 로그인하면 메인 화면을 사용할 수 있습니다.

## 게시물 기능

- 내용 또는 첨부 파일만으로 게시할 수 있습니다.
- 게시물과 댓글은 작성자만 삭제할 수 있습니다. 삭제는 확인창에서 확정합니다.
- 게시물·댓글 좋아요는 계정당 한 번이며, 다시 누르면 취소합니다.
- 게시물의 저장 버튼으로 북마크하고 왼쪽 저장됨 메뉴에서 확인합니다. 다시 누르면 저장을 취소합니다.
- 댓글은 2,000자까지 입력할 수 있습니다.
- 사진(JPEG/PNG/GIF/WebP), 영상(MP4/WebM/Ogg)을 최대 4개, 각 20MB까지 첨부합니다. 재생 가능 여부는 브라우저 코덱 지원에 따릅니다.

## 저장 구조

`js/auth.js`는 기존 회원가입/로그인/비밀번호 재설정을 처리하고 `js/feed.js`는 피드 기능을 처리합니다.

- localStorage: 회원, 현재 계정, 게시물·댓글·좋아요·북마크 메타데이터
- IndexedDB `fakebookMedia` / `files`: 첨부 파일 원본 Blob
- 게시물·댓글의 `authorId`로 작성자를 구분하고 `likedBy`, `savedBy`에 계정 ID를 기록합니다.
- 기존 게시물은 이름이 단 한 계정과 일치하는 경우에만 작성자로 연결합니다. 이름이 중복되거나 계정이 없으면 삭제 권한을 자동 부여하지 않습니다.
- 기존 익명 좋아요 수는 유지하지만 과거 누른 사람이 기록되지 않았으므로 그 수는 취소할 수 없습니다. 새 좋아요는 취소할 수 있습니다.
- 기존 HTML의 고정 예제 게시물은 실제 상호작용 대상인 저장 게시물 목록으로 대체했습니다.

이 프로젝트는 로컬 학습용입니다. 다른 기기와 데이터가 공유되지 않으며 브라우저 데이터를 지우면 사라집니다. 회원 비밀번호는 기존 구현대로 평문 저장되며 작성자 권한도 클라이언트에서 확인합니다.

## 아이콘 버튼과 답글

좋아요는 하트(선택 시 빨강), 저장은 책갈피(선택 시 파랑) SVG 버튼입니다. 키보드로 조작할 수 있고 스크린리더용 이름과 선택 상태를 제공합니다.

댓글의 **답글 달기**를 눌러 답글을 작성합니다. 답글은 부모 댓글 아래에 한 단계 들여써 표시되며 좋아요·취소와 작성자 삭제를 지원합니다. 부모 댓글을 삭제하면 답글도 함께 삭제됩니다(확인창 안내). 기존 댓글도 답글을 추가할 수 있고 기록은 새로고침 후 유지됩니다.


## 친구·프로필

- 메뉴의 집·두 사람·책갈피 SVG 아이콘으로 홈/친구/저장됨을 이동합니다. 아이콘에는 접근성 이름과 선택 상태가 있습니다.
- 친구 화면: 추천, 요청, 모든 친구, 이름 검색. 사진·이름을 누르면 상세 프로필을 봅니다.
- 최초 실행 시 가상 인물 12명의 이름과 SVG 일러스트 아바타를 무작위 생성해 `fakebookDummyProfiles`에 저장합니다. 외부 이미지 API나 네트워크 요청은 없습니다.
- 요청 탭의 2개 요청은 시연용이며 확인/삭제할 수 있습니다. 추천의 친구 추가는 즉시 완료됩니다. 추천 삭제는 숨기기이며 ‘삭제한 추천 다시 보기’로 복원할 수 있습니다.
- 친구/숨긴 추천/처리한 요청은 `fakebookFriends:<계정ID>`에 계정별로 저장합니다. 실제 사용자에게 요청을 보내거나 알림을 전송하지 않습니다.
- 사이드바 프로필 사진 또는 ‘프로필 설정’에서 내 프로필을 열고 표시 이름, 소개(200자), 생년월일(선택), 사진을 변경합니다. JPG/PNG/WebP 최대 5MB를 받아 긴 변 512px 이하 JPEG로 변환합니다. 기본 사진으로 되돌리기와 저장/취소를 지원합니다.
- `fakebookProfiles`의 계정 ID별 프로필을 게시물·댓글·답글에서 조회하므로 기존 상호작용과 작성자 권한을 보존합니다. 표시 이름과 회원가입 이름은 별개이며 로그인·비밀번호 찾기는 원래 가입 정보를 사용합니다.
- GitHub Pages에서도 동작하지만 모든 기록은 같은 출처의 브라우저 안에 저장됩니다. 브라우저 데이터 삭제 시 사라지며 기기 간 공유하지 않습니다.

검사: `node tests/feed.cjs`, `node tests/social.cjs`.

브라우저 검사: 프로젝트를 `python -m http.server 8765`로 실행한 뒤 `node tests/social-browser.cjs` (Playwright와 Chromium 설치 필요, `CHROMIUM_PATH`로 실행 파일 경로 지정 가능). 이 변경 작업 환경에서는 Chromium 실행이 차단되어 브라우저 검사는 완료하지 못했습니다.


## 프로필 타임라인과 생년월일

- 기본 프로필 사진은 `img/default-avatar.svg`의 회색 사람 실루엣입니다. 사진을 등록하지 않았거나 기본 사진으로 변경하면 적용됩니다. 사이트 로고와 더미 친구의 기존 일러스트는 유지됩니다.
- 내 프로필/게시물 작성자/친구 사진·이름을 누르면 해당 계정의 게시물만 최신순으로 표시합니다. 사진·영상, 좋아요·저장·댓글·답글 및 작성자 수정·삭제는 동일한 피드 렌더러를 사용합니다. 글이 없으면 빈 상태를 표시합니다.
- 더미 친구는 한 명당 2개의 텍스트 샘플 글을 가집니다. `fakebookPosts`에 일정한 ID와 `demo: true`로 저장하므로 재접속해도 상호작용을 유지하고 중복 생성하지 않습니다. 샘플은 홈에는 표시하지 않고 프로필과 북마크한 저장됨 화면에서 표시합니다.
- 내 친구 수는 계정별 실제 친구 목록 수입니다. 가상 프로필의 친구 수는 시연용 기본 수에 이 브라우저에서 친구로 추가한 회원 수를 더한 값이며, 화면에 가상 프로필로 표시합니다.
- 새 회원가입은 생년월일을 입력하며 기본 비공개입니다. 기존 계정은 등록된 값이 없으면 미설정으로 표시하고 프로필 설정에서 입력할 수 있습니다. 설정에 저장한 생년월일이 회원가입 값을 우선하며, 빈 값으로 지우는 것도 가능합니다. 유효한 1900년~오늘 날짜만 받습니다.
- 프로필 설정의 ‘생년월일 공개’를 켜면 다른 계정의 프로필 화면에서도 날짜를 표시합니다. 끄면 본인에게만 ‘나만 보기’로 표시하며 다른 계정의 화면과 프로필 조회 결과에는 날짜를 넣지 않습니다. 이는 브라우저 화면 표시 제어이며, 로컬 저장소를 암호화하거나 서버 접근 제어를 제공하는 기능은 아닙니다.

추가 회귀 검사: `node tests/profile-feed.cjs`, `node tests/signup-birthday.cjs`. DOM 모형으로 social/feed 통합 동작, 생년월일 공개·비공개와 회원가입 검증을 확인합니다. 실제 브라우저 렌더링·첨부 파일 디코딩 검증은 별도로 필요합니다.


## 시간에 따른 가상 활동

`js/ambient.js`는 외부 서버나 실제 사용자에게 연락하지 않고 브라우저 안에서 더미 활동을 생성합니다.

- 더미 인물은 40명입니다. 기존 인물의 ID·이름·소개·생년월일은 유지하면서 사진을 기본 실루엣/얼굴 일러스트/풍경/꽃으로 다양화합니다. 이미지는 로컬 SVG 또는 인라인 SVG이므로 외부 이미지 서비스가 필요하지 않습니다.
- 추천은 매 페이지 접속 시 순서를 새로 섞어 최대 10명을 표시합니다. 같은 접속 중에는 유지하며 친구·대기 요청·삭제한 추천은 제외합니다. 친구 추가/삭제 등으로 대상이 바뀌면 남은 후보로 채웁니다. 계정별 친구 관계는 분리됩니다.
- 각 프로필에는 20가지 일상 글 중 0~3개를 최초 무작위 배정하고 2주 이내의 작성 시각으로 저장합니다. 기존 반복 샘플 글은 새 문구로 바꾸되 좋아요·저장·댓글이 있는 글은 배정 수보다 많아도 보존합니다. 새로고침할 때 글이나 사진을 재추첨하지 않습니다.
- 새 계정의 첫 메인 접속 때 요청을 0~4개 배정합니다. 기존 계정의 요청은 보존하면서 만료 시각을 부여합니다. 이후 8~35분 간격으로 1~2개가 도착하며 대기 요청은 최대 10개입니다. 요청은 도착 후 25~150분 뒤 자동 취소되고, 취소된 대상은 12시간 동안 다시 요청하지 않습니다. 친구로 수락한 관계는 만료되지 않습니다.
- 본인이 작성한 최근 7일 이내의 글에는 게시 1~4분 후부터 2~12분 간격으로 반응을 시도합니다. 각 시도는 70% 확률로 반응하며 그중 24%는 댓글을 선택합니다. 친구인 더미에게 반응할 가중치를 줍니다. 같은 인물의 중복 좋아요와 반복 자동 댓글을 방지합니다.
- 게시물당 자동 좋아요 최대 12개/자동 댓글 최대 3개입니다. 직접 받은 반응을 삭제해도 생애 생성 횟수는 초기화하지 않아 무한 재생성하지 않습니다. 실제 사용자의 좋아요·댓글과 기존 기록은 유지합니다.
- 한 번의 갱신에서는 전체 반응 최대 6개, 글당 최대 2개, 새 요청 최대 2개만 생성합니다. 긴 미접속 기간을 전부 재생하지 않고 만료 처리를 먼저 한 뒤 다음 갱신 시각을 미래로 예약합니다.
- 열린 페이지는 20초마다 확인합니다. 프로필 설정 또는 입력 중에는 자동 갱신을 미뤄 편집 중인 내용을 방해하지 않습니다. 닫힌 브라우저에서는 실행되지 않으며 다음 접속/포커스 복귀 때 경과 시간을 처리합니다. 지원하는 브라우저에서는 Web Locks로 열린 탭의 주기적 처리를 직렬화합니다.
- `fakebookFriends:<ID>`에 요청 만료·다음 도착·재요청 대기 정보를, 각 게시물의 `ambient`에 반응 예약·생성 횟수를 저장합니다. 이 설정은 배포 후에도 해당 브라우저 안에서만 작동합니다.

검사: `node tests/ambient.cjs`는 주입한 시계와 난수로 수백 번의 시간 경과, 요청 만료·상한·계정 분리, 반응 중복·횟수·미접속 배치 제한, 샘플 이전과 저장 실패를 검증합니다. 기존 피드·프로필·회원가입 회귀 검사도 함께 실행합니다. 브라우저 화면 및 실제 타이머의 시각적 검증은 아직 완료하지 못했습니다.


## 로컬 프로필 이미지 팩

- `img/profiles/`에 사진 12장과 얼굴 일러스트 8개를 포함합니다. 풍경 5장, 꽃 2장, 동물 2장, 일상 사물 3장과 8종의 얼굴 SVG를 기본 실루엣과 섞습니다.
- 사진은 Unsplash에서 미리 내려받은 256×256 WebP입니다. 사진 전체가 약 120KB로 작으며 실행 시 외부 서버나 API 키가 필요하지 않습니다. 원본 URL과 사용 조건은 `img/profiles/SOURCES.md`, `sources.json`에 있습니다.
- 40명 기준 기본 8명·얼굴 8명·풍경 8명·꽃 6명·동물 6명·사물 4명으로 무작위 배정합니다. 배정값을 `avatarAssetVersion`과 함께 저장해 새로고침 후 유지합니다.
- 기존 더미 프로필은 처음 한 번만 새 이미지 팩으로 교체합니다. 이름·ID·소개·생년월일·게시물 배정·친구 관계와 상호작용은 유지합니다. 사용자가 직접 올린 내 프로필 사진도 변경하지 않습니다.
- 친구 목록·프로필 상세·게시물/댓글의 작성자 이미지·사이드바는 로딩에 실패하면 익명 기본 아바타로 바뀝니다. 기본 이미지도 실패할 때 재시도 루프가 생기지 않도록 오류 핸들러를 해제합니다. 동적 이미지는 lazy loading과 비동기 디코딩을 사용합니다.
- 검사: `node tests/profile-images.cjs`, 기존 `tests/social.cjs`에 기본 이미지 fallback 검사 추가. 이미지 파일 디코딩·크기·출처 기록, 경로 존재, 다양한 배정과 기존 데이터 보존을 확인했습니다. 실제 브라우저 화면 검증은 아직 완료하지 못했습니다.


## 다양한 홈 피드와 더미 게시물 상호작용

- 프로필 사진을 15장 더 추가해 사진 27장 + 얼굴 SVG 8종 + 기본 아바타를 사용합니다. 추가 사진도 256×256 WebP로 저장하고 원본 URL·사용 조건을 `img/profiles/SOURCES.md`, `sources.json`에 기록했습니다.
- 더미 사진 배정을 버전 2로 한 번 갱신합니다. 40명 기준 기본 4명·얼굴 8명·풍경 11명·꽃 5명·동물 5명·사물 7명입니다. 이름·친구 관계와 사용자 프로필 사진은 유지합니다.
- ‘알 수도 있는 사람’은 후보를 섞은 뒤 이미지 경로를 기준으로 중복을 제거해 최대 10명을 선택합니다. 기본 사진도 목록 안에 최대 한 번 표시하며 후보가 부족하면 적게 표시합니다. 요청/모든 친구 목록에는 실제 해당 인물 전부를 보여줍니다.
- 일상 글 템플릿은 50개이고, 각 글에는 내용에 맞춘 댓글 2~5종을 직접 준비했습니다. 각 더미 글에 이 중 2~5개의 댓글을 다른 더미 작성자에게 배정하고, 해당 글 작성자 이외의 더미에게 초기 좋아요 0~25개를 배정합니다. 댓글은 프로필 링크, 좋아요·답글 기능과 연결됩니다.
- 초기 댓글/좋아요 배정은 저장하므로 재접속 때 중복 생성하거나 수가 바뀌지 않습니다. 사용자가 기존에 쓴 댓글/답글·좋아요·북마크는 유지합니다. 현재 50종에 속하지 않는 별도 내용은 자동으로 덮어쓰지 않습니다.
- 내용 확장은 한 번만 수행하며, 기존 상호작용이 없는 샘플 글을 50종에서 재배정합니다. 상호작용이 있는 글의 본문은 그대로 두고 그 내용에 맞는 댓글을 붙입니다. 기존 샘플 배정 개수(0~3개)는 유지합니다.
- 홈은 실제 저장 게시물에 무작위 더미 글 최대 10개를 섞어 최신순으로 보여줍니다. 더미는 한 작성자당 한 개, 같은 내용당 한 개를 선택하고 실제 게시물과 같은 내용도 제외합니다. 홈을 오가거나 좋아요·댓글을 눌러도 선택은 유지하며 새 접속에서 다시 선택합니다. 프로필과 저장됨에서는 기존처럼 해당 글을 모두 볼 수 있습니다.
- 추가 검사: `node tests/depth.cjs` — 50종/댓글 수 범위, 댓글의 템플릿 일치·작성자·작성시각, 초기 좋아요/댓글 저장과 사용자 기록 보존, 추천 사진 중복 제거, 홈의 글/작성자 중복 제거 및 빈 상태를 확인합니다. 실제 브라우저 화면 검증은 아직입니다.


## 버튼 상호작용 시 화면 흔들림 방지

- 좋아요/북마크 후 피드 전체를 비우지 않고 기존 버튼의 개수·색상·접근성 상태만 갱신합니다. 댓글·답글 좋아요에도 동일하게 적용합니다.
- 게시물 ID와 본문/댓글 구조를 비교해 변경되지 않은 카드는 유지합니다. 댓글 추가·수정·삭제, 본문 수정 시에는 해당 카드만 갱신하며 첨부 목록이 같으면 사진·영상 요소와 Blob URL을 재사용합니다.
- 목록에서 실제 사라진 카드의 URL만 해제합니다. 저장됨에서 저장을 취소하면 해당 카드가 사라지고 마지막 카드였다면 빈 상태를 표시합니다. 홈의 내 글 우선 정렬과 세션 내 더미 선택은 유지합니다.
- 좋아요 개수 영역은 숫자 너비와 굵기를 고정해 개수/선택 상태 변화에 따른 버튼 폭 변화를 줄였습니다.
- `node tests/feed-stability.cjs`: 카드·버튼·첨부 요소의 동일성, 포커스와 편집 초안 유지, 이미지/영상 재조회 방지 및 재생 위치 보존, 저장 실패 시 상태 유지, 댓글 갱신 시 다른 카드 보존, 저장 취소 후 URL 해제를 DOM 모형으로 검사합니다. 기존 feed/profile-feed 검사도 통과했습니다. 실제 브라우저의 시각적 스크롤·레이아웃 검증은 아직 완료하지 못했습니다.


## 문맥에 맞는 부정적 댓글과 제지 답글

- 더미 게시글 50종 각각에 부정적 댓글과 그 댓글을 제지하는 답글을 한 쌍씩 작성했습니다. `TEMPLATE_PAIRS`의 50개 쌍은 `CONTENT`의 게시글 인덱스와 정확하게 연결되며, 두 문구를 서로 다른 목록에서 무작위로 뽑지 않습니다.
- 직접 작성한 글은 러닝·직접 만든 요리·다녀온 여행·마친 공부/과제·완독·영화 감상·공간 정리·코드 해결의 8개 명확한 패턴만 처리합니다. 각 패턴에 전용 댓글/답글 쌍이 있습니다. 자유 입력을 AI로 이해하는 방식이 아니라 보수적인 규칙 방식이며, 질문·부정·어려움·여러 주제가 섞인 글이나 패턴을 확인할 수 없는 글에는 부정적 댓글을 만들지 않습니다.
- 더미 글의 5% 후보 확률과 글당 생애 최대 1개·연속 방지·5분 간격은 유지합니다. 내 글은 아래의 확정 시연 예약 방식으로 대체합니다. 실제 비율은 맥락 확인과 횟수 제한 때문에 더 낮을 수 있습니다.
- 65% 확률로 2~10분 뒤 다른 더미의 제지 답글을 예약합니다. 댓글과 같은 쌍의 답글만 사용하며, 예약 후 본문이 바뀌어 원래 맥락과 맞지 않으면 취소합니다. 댓글당 최대 1개·한 번의 경과 처리당 최대 2개이며 논쟁이 연쇄 생성되지 않습니다. 부모 댓글/게시물이 삭제되면 예약도 사라집니다.
- 댓글 숨기기/다시 표시 버튼과 프로필 설정의 시뮬레이션 끄기 항목을 제거했습니다. 예전 `hiddenBy`, `fakebookSimulation:<ID>`는 더 이상 표시/생성을 제어하지 않습니다. 기존 댓글을 다시 보여주되 이미 취소된 예약을 재개하지는 않습니다. 생년월일 공개 설정 등 다른 프로필 설정은 유지합니다.
- 옛 맥락 불일치 자동 댓글은 한 번 정리합니다. 사용자의 좋아요·답글·수정 이력이 없는 댓글은 현재 글의 전용 쌍으로 수정하고 기존 자동 제지 답글도 같은 쌍으로 고칩니다. 맥락을 확인할 수 없으면 이력이 없는 자동 댓글만 제거합니다. 사용자 상호작용이 있는 옛 댓글은 본문/기록을 보존하고 어긋나는 새 답글 예약만 취소합니다.
- `tests/civility.cjs`는 50종의 정확한 쌍, 8개 자유 입력 패턴과 불확실한 입력 건너뛰기, 기존 확률/횟수/지연/작성자/배치 제한, 게시글 수정 시 예약 취소, 옛 자동 댓글 이전과 기록 보존을 검사합니다. `tests/feed-stability.cjs`, `tests/social.cjs`에서 새 버튼/설정이 없고 예전 숨김 값이 댓글을 감추지 않는지도 검사합니다. 실제 브라우저 화면 검증은 아직입니다.


## 내 게시글의 확정 시연 스레드

- 현재 로그인한 사용자의 글에는 확률과 무관하게 부정적 댓글 1개와 그 아래 제지 답글 1~2개를 생성합니다. 더미 글과 다른 계정의 글에는 이 확정 처리를 적용하지 않습니다. 기존 좋아요·일반 댓글 시뮬레이션은 유지합니다.
- 처음 글을 확인한 시점에 1~3분 뒤 부정적 댓글을 예약합니다. 실제 댓글을 생성한 시점부터 다시 1~3분 뒤 제지 답글을 예약합니다. 페이지의 20초 확인 주기 및 입력 중 갱신 유예에 따라 실제 표시가 조금 늦어질 수 있습니다.
- 제지 답글 개수(1 또는 2)는 처음 예약할 때 무작위로 정하고 저장합니다. 각 답글은 부정적 댓글 작성자·원글 작성자·다른 제지 답글 작성자와 서로 다른 더미가 씁니다. 2번째 답글은 일반적인 존중·제지 표현을 사용합니다.
- 50종 템플릿/명확한 주제는 기존 전용 부정 댓글·제지 문구를 사용합니다. 문맥을 확실히 판단할 수 없는 자유 입력이나 사진만 있는 글은 구체적인 내용을 추측하지 않는 일반 비꼼·제지 문구를 사용합니다. 원문이 예약 뒤 바뀌면 제지 답글은 일반 문구로 전환합니다.
- 이 기능은 기존 7일 제한과 별도로 오래된 내 글에도 예약합니다. 한 번의 확인에서 새 부정 댓글 최대 2개, 제지 답글 최대 2개만 생성해 과도한 동시 생성을 줄입니다. 장기간 미접속 뒤에도 부모 댓글을 만든 즉시 제지 답글까지 한꺼번에 생성하지 않습니다.
- 기존 부정적 댓글이 있으면 재사용하고 이미 제지 답글이 있으면 보존합니다. 글의 `ownConversation`에 예약/진행/완료를 저장하며 댓글의 `defensePlan`에 목표 답글 수와 시각을 저장합니다. 새로고침이나 재접속으로 중복 생성하지 않습니다. 부모를 삭제한 경우 다시 만들지 않습니다.
- 예약 메타데이터만 갱신될 때는 피드 카드를 다시 만들지 않아 기존 버튼 상호작용 안정성을 유지합니다.
- 검사: `node tests/guaranteed-own.cjs`에서 높은 난수에서도 확정 생성, 1~3분 예약 경계, 1·2개 답글, 서로 다른 작성자, 맥락/일반 문구, 오래된 글, 재접속·기존 댓글·삭제 처리·계정 경계·미접속 단계 처리·저장 실패를 확인합니다. 실제 브라우저 화면 검증은 아직입니다.
